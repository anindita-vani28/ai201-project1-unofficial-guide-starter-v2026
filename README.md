# Unit 1

## What This Does

This project indexes the `campus_life` corpus and answers questions about dining, housing, coursework, library hours, and campus logistics. It retrieves relevant chunks from the corpus, checks whether the best match is close enough to answer, and then generates a grounded answer that names at least one source document.

The system is designed for concise, campus-focused questions where the answer is present in a short document or paragraph rather than in a long narrative.

## Chunking Strategy

**Chunk size:** paragraph-based chunking, not a fixed 800-character window

**Overlap:** none

I used paragraph boundaries for this corpus because the documents are short, fact-like posts and many of them are only a few sentences long. A fixed-size chunker would split these into fragments that lose meaning. The custom `split_documents` function in `chunker.py` breaks on blank-line paragraph boundaries and merges a very short leading paragraph into the next paragraph when needed so that the chunk still reads like a complete thought.

This fits the campus documents better than a fixed window because the useful information is often contained in a single paragraph rather than across a long character span.

## Sample Answer

**Question:** Which floors in Aldridge Hall are designated as quiet floors?

**Answer:**

```
Based on the provided documents, floors 3 and 4 in Aldridge Hall are designated as quiet floors.

```

**My relevance cutoff:** 0.6

I kept the cutoff at `0.6` because the in-corpus questions clustered well below it and the out-of-scope questions were clearly above it. The gate separates the two groups cleanly, so changing the threshold would not improve the system without evidence.

## How I Used AI

**1.** I asked for help choosing a retrieval cutoff based on distance distributions, and the model suggested comparing the best distances for in-corpus vs. out-of-scope questions. I used that idea to check the actual numbers, and I kept the threshold at `0.6` because it cleanly separated the two groups.

**2.** I asked for feedback on the paragraph-merging logic in `chunker.py` after noticing that short intro paragraphs were getting split off from their main content. The model suggested merging a very short leading paragraph with the next paragraph; I implemented that logic directly in `split_documents` so the chunks read as complete thoughts.

## Diagnoses

The main issue in the early pass was not a broken threshold or a retrieval failure: the system was already separating the in-corpus and out-of-corpus questions correctly. The only criterion that remained unmeasured was response time, and that requires an explicit timing test rather than a visual inspection of the output.

The chunking strategy was a good fit for this corpus because the documents are short, paragraph-driven, and factual. The custom paragraph-based logic helped keep each chunk readable without fragmenting helpful information.

## The Improvement

**What I changed:** I kept the relevance cutoff at `0.6` and validated it against the actual distance groups; I also implemented the paragraph-based `split_documents` strategy in `chunker.py`.

**Why I picked it:** The evidence showed a clean separation between relevant and unrelated questions: in-corpus distances were between 0.182 and 0.448, while out-of-scope distances ranged from 0.787 to 0.923.

## What's Still Broken

The only criterion still not verified is response time. The project has not yet run a measured timing check for the five test questions, so I would not claim Criterion 5 as passed without a dedicated benchmark.

## What I'd Do Differently

If I had more time, I would add a small timing harness around the five question prompts and record the p50/p95 response times. That would make the speed criterion measurable in a repeatable way instead of leaving it as an unverified assumption.
